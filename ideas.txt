## **Visão Geral do Projeto**

**Nome do Projeto**: **CargaLog**

**Objetivo**: Registro e análise de progressão de carga em exercícios de musculação. O sistema permite que os usuários registrem os dados dos seus treinos, visualizem a evolução do desempenho ao longo do tempo, e gerenciem seus históricos.

**Stack Tecnológica**:

* **Back-End**:

  * **NestJS (Fastify)**: Framework para construção da API com foco em performance e escalabilidade. Utiliza **Fastify** para garantir alta performance nas requisições.
  * **Prisma**: ORM para interação com o banco de dados **PostgreSQL** (via **Supabase**).
  * **Supabase**: Banco de dados **PostgreSQL** com autenticação integrada e outras funcionalidades como **storage**.

* **Front-End**:

  * **React Native (CLI)**: Para o aplicativo móvel (iOS/Android).
  * **React**: Para o dashboard web.
  * **Redux**: Para gerenciamento de estado nos apps **React** e **React Native**.

* **Infraestrutura**:

  * **Docker**: Containerização dos microservices para facilitar o deploy e a escalabilidade.
  * **Kubernetes**: Orquestração de containers para escalabilidade automática e alta disponibilidade.
  * **CI/CD**: Pipeline de integração e entrega contínua utilizando ferramentas como **GitHub Actions**, **Jenkins**, ou **GitLab CI**.

* **Segurança**:

  * **JWT (JSON Web Tokens)**: Para autenticação e autorização nos microservices.
  * **Criptografia**: Uso de **bcrypt** ou **argon2** para criptografia de senhas, e **TLS** para comunicação segura entre os serviços.

---

## **2. Arquitetura de Microservices no CargaLog**

A arquitetura de **microservices** no **CargaLog** será modular, com cada serviço responsável por uma parte específica da aplicação. Essa abordagem oferece escalabilidade, isolamento de falhas e flexibilidade para futuras melhorias.

### **1.1 Microservice de Autenticação (Auth Service)**

* **Responsabilidade**: Gerencia a **autenticação e autorização** dos usuários.
* **Tecnologia**: **Supabase** para lidar com autenticação e geração de tokens JWT.
* **Funcionalidade**:

  * Registro de novos usuários.
  * Login e logout de usuários.
  * Geração e validação de tokens JWT.
  * Autorização com base em roles/permissions.

  **Exemplo de endpoints**:

  * **POST /auth/login**: Realiza o login do usuário e retorna o JWT.
  * **POST /auth/register**: Cria um novo usuário.
  * **GET /auth/validate**: Valida o token JWT para sessões ativas.

### **1.2 Microservice de Treino (Workout Service)**

* **Responsabilidade**: Gerencia os **registros de treino**, permitindo ao usuário registrar, editar, excluir e consultar os dados de seus treinos.
* **Tecnologia**: **NestJS + Fastify** para garantir desempenho e escalabilidade.
* **Funcionalidade**:

  * CRUD de treinos (criar, ler, atualizar, excluir).
  * Armazenamento de dados de treino (exercício, carga, repetições, data).
  * Relacionamento entre treino e usuário (via **usuario_id**).

  **Exemplo de endpoints**:

  * **POST /treinos**: Cria um novo registro de treino.
  * **GET /treinos**: Retorna todos os registros de treino com paginação.
  * **GET /treinos/{id}**: Retorna os dados de um treino específico.
  * **DELETE /treinos/{id}**: Remove um registro de treino.

### **1.3 Microservice de Análise de Dados (Analytics Service)**

* **Responsabilidade**: Realiza os **cálculos de progressão** dos treinos e gera **gráficos de evolução** para o dashboard do usuário.
* **Tecnologia**: **NestJS + Fastify** ou outras tecnologias de análise de dados, dependendo da complexidade.
* **Funcionalidade**:

  * Cálculos de recordes pessoais (PR) por exercício.
  * Geração de gráficos de evolução ao longo do tempo (ex: gráfico de linha mostrando a evolução da carga).

  **Exemplo de endpoint**:

  * **GET /treinos/stats**: Retorna o recorde pessoal (PR) e gráficos de progresso de um exercício específico.

### **1.4 Microservice de Front-End (React Native e React Web)**

* **Responsabilidade**: Serve como **interface de usuário** para o sistema, tanto no **mobile** quanto no **web**.
* **Tecnologia**: **React Native** para o aplicativo móvel e **React** para o dashboard web.
* **Funcionalidade**:

  * Exibição de dados de treino (tabela de históricos e gráficos).
  * Interações de usuário (registrar treino, ver progresso, editar dados).
  * Comunicação com os microservices back-end através de APIs.

  **Exemplo de integração**:

  * O **React Native** consumirá os endpoints do **Workout Service** e do **Analytics Service** para exibir os dados de treino e gráficos.
  * O **React** consumirá os mesmos endpoints para exibir o histórico de treinos e progresso no web dashboard.

---

### **1.5 Microservice de Comunicação Assíncrona (Opcional)**

* **Responsabilidade**: Gerencia a comunicação assíncrona entre microservices (caso o sistema precise de comunicação desacoplada, por exemplo, em operações em segundo plano ou notificações).
* **Tecnologia**: **RabbitMQ** ou **Apache Kafka**.
* **Funcionalidade**:

  * Envio de eventos para outros microservices (como notificações de novos treinos registrados ou alertas de progresso).

  **Exemplo de uso**:

  * Quando um novo treino é registrado, o **Workout Service** pode enviar uma mensagem para o **Analytics Service** para atualizar os dados de progresso.

---

### **2. Comunicação Entre os Microservices**

* **Frontend (React/React Native)** se comunica com os microservices **Autenticação**, **Treino** e **Análise de Dados** através de **APIs RESTful**.
* **Microservices** podem se comunicar entre si usando **mensagens assíncronas** ou chamadas API, dependendo da necessidade de desacoplamento ou desempenho.

---

### **3. Stack Tecnológica Organizada**

**Back-End**:

* **NestJS + Fastify**: Para a construção da API.
* **Prisma**: ORM para interação com **PostgreSQL** (via **Supabase**).
* **Supabase**: Banco de dados **PostgreSQL** com autenticação integrada.
* **RabbitMQ ou Kafka** (opcional): Comunicação assíncrona entre microservices.
* **API Gateway** (opcional): Usado para roteamento de tráfego e controle de acesso entre microservices.

**Front-End**:

* **React Native**: Para o aplicativo móvel.
* **React**: Para o dashboard web.
* **Redux**: Para gerenciamento de estado no front-end.

**Infraestrutura**:

* **Docker**: Containerização dos microservices.
* **Kubernetes**: Orquestração de containers.
* **CI/CD**: Pipeline de integração e entrega contínua.

**Segurança**:

* **JWT (JSON Web Tokens)**: Para autenticação e autorização nos microservices.
* **Criptografia**: Uso de **bcrypt** ou **argon2** para criptografia de senhas, e **TLS** para comunicação segura entre os serviços.

---

### **4. Conclusão**

A arquitetura de **microservices** para o **CargaLog** é estruturada de forma modular, com cada serviço responsável por uma parte específica da aplicação. Essa abordagem garante **escalabilidade**, **isolamento de falhas** e **flexibilidade** para melhorias futuras.

* **Microservices** como **Autenticação**, **Treino**, **Análise de Dados** e **Front-End** permitem que cada serviço seja escalado independentemente conforme as necessidades do sistema.
* A **comunicação entre microservices** pode ser feita via **APIs RESTful** ou **mensagens assíncronas** com **RabbitMQ/Kafka**, dependendo da necessidade de desacoplamento ou performance.
